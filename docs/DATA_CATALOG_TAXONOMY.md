# 宏观指标目录树设计约束

目录树是产品的检索结构，不是各环境独立维护的手工状态。唯一的可部署定义位于 `src/lib/data/globalCatalogTaxonomy.ts`，并由 `data:rebuild-global-catalog-layout` 重建。

## 固定顶层

所有国家只使用以下九个顶层主题，与美国保持一致：

1. 国民经济
2. 通胀与价格
3. 劳动力市场
4. 货币政策与流动性
5. 利率与信用市场
6. 金融条件与银行
7. 财政与公共债务
8. 地产与建筑
9. 对外与汇率

每项指标必须有一个顶层主题和一个业务子层级；不得以来源机构、抓取方式或“其他数据”作为顶层。中国官方数据按 CPI、PPI、PMI、工业增加值、GDP、固定资产投资、消费、地产、财政、货币信用、外部部门等业务口径继续细分。

## 末端负载

- 子层级是指标列表的末端；单个子层级最多 `48` 条指标。
- 达到上限时，先按经济含义拆分（例如 PPI 的采矿、消费品制造、能源材料、装备制造、公用事业）。
- 仍超过上限时，按稳定排序切为带序号的同主题分段，避免一个末端组无法浏览。
- `未分配` 只能用于缺失国家/业务元数据的异常指标；正常部署的目录重建会把它视为失败。

## 变更流程

1. 新接入指标的 seed 必须写入 `countryCode`、`catalogCategory`、`displayName`。
2. 在 `resolveGlobalCatalogPlacement` 增加需要的精细规则和子层级；不要仅靠管理端拖拽。
3. 运行 `npm run data:rebuild-global-catalog-layout -- --dry-run`，确保未分配与超限末端均为零。
4. 推送 `main` 后，部署中的 `data:apply` 会重建云端布局；本机与香港环境使用同一规则。
