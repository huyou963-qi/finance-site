# 事件筛选第 2 轮：结果解释与列表、主图一致性

日期：2026-10-28。状态：本地实现与验证，尚未部署。沿用左侧分页、单行工具栏和 180px 默认高度。

## 基线与问题

第 1 轮以来源区分筛选，但系统列表、用户列表、主图仍共用同一个去重集合。用户注释可能吞掉系统列表的对应记录；若注释仅关闭上图，去重后的系统标记也可能被间接挡掉。原排除统计只有总量，用户无法定位事件未出现的原因；加载失败与空数据缺少可操作的区分。

本轮假设：保留各来源记录，只对可上图候选做事实合并；由同一筛选流程产生原因和统计，即可解释列表与主图的合理差异。

## 交付

1. **来源列表与主图投影分离**：两类列表各自保留符合条件的记录。主图先排除关闭上图或单独隐藏的记录，再按原有保守事实判定合并；仍保持用户注释、共享记录、SEC 的代表优先级。系统与用户都存在的事实可在两页分别查看。
2. **逐条解释与互斥统计**：筛选函数同时返回全部不满足条件，包括时间范围、来源、类型、重要度、公司细类、预期差、搜索、人物、机构、本地标签及隐藏事件。总计按首个原因归类，单条说明展示所有原因，避免重复加总。
3. **结果说明浮层**：工具栏展示“列表 / 候选 / 合并”，点开查看阶段统计、排除原因、原始发生时间与查询返回的关联依据。卡片增加“说明”入口，被合并记录可跳到对应系统或用户记录；选中列表记录会高亮主图代表。
4. **恢复与重试**：浮层支持清除当前来源内容条件、检查来源与包范围、恢复当前来源隐藏事件、重试加载系统事件。重试不修改另一来源的偏好。
5. **空状态分类**：区分来源关闭、包未导入、包全部停用、包范围不适用、事件在区间外、被内容条件排除、查询无结果、正在加载、加载失败。失败时明确说明覆盖情况未知，用户事件仍可查看。
6. **候选加载与分页**：来源开关和客户端筛选不在取候选时提前丢弃记录，保证关闭来源后仍可解释排除原因；服务端保留共享与 SEC 的来源记录。客户端分页按稳定记录 ID 消除重复传输的 SEC 记录。切换查询即停止展示上一个查询的远端结果；失败可重试。

## 统计定义

- 已加载 = 区间外 + 区间内。
- 区间内 = 内容筛除 + 本来源列表。
- 本来源列表 = 关闭本类上图 + 单条隐藏标记 + 合并到其他记录 + 本来源作为代表的主图候选。
- 上述展示阶段互斥；“候选”不等于实际绘制标记数，仍需考虑 K 线覆盖、交易日对齐和同根聚合。
- 服务端先按资产、关联范围、显式标签与时间取候选，因此客户端无法统计全库未返回事件。界面明确“当前查询已加载集合”，不宣称完整历史覆盖。SEC 仍有服务端单次披露数量上限。
- 用户包的停用、范围不适用、当前适用按包统计；未加载包中的事件不混入已加载事件计数。本轮未改写跨包身份规则。

## 验证与迭代结果

新增回归复现并修正了以下问题：

- 同一事实在来源列表消失：现在两来源记录都保留，只有主图候选合并。
- 用户事件不上图却挡住系统标记：现在先判定上图资格再合并，系统标记正常保留。
- 多原因排除计数重复：现在首个原因计数、单条完整展示，总数满足分解等式。
- 分页重复返回 SEC：按稳定记录 ID 去除重复传输，不把它计为新增事实。
- 切换资产时显示旧查询结果：现在结果与查询键绑定，切换后旧结果立即不可见。
