# 界面多语言（中文 / English）

## 现状（阶段 0 已完成）

- 框架：`next-intl`（不分路由模式）。语言存在 cookie `NEXT_LOCALE`，**URL 不变**，不加 `/en` 前缀。
- 默认中文。英文文案与中文深合并，**英文缺的键显示中文**，所以可以一页一页地翻，不会出现空白。
- 开关：功能目录里的 `site-language-en`（`kind: "setting"`，分组「站点」），默认 **开发中**。
  - 切换入口：电脑版顶栏右侧、手机版导航抽屉底部「语言」，都经 `useVisibleFeatures().can("site-language-en")` 过滤。
  - 服务端兜底：`src/i18n/request.ts` 只在 cookie 为 `en` 时查功能权限，无权身份按中文渲染。
  - 上线：管理员在 `/admin/feature-access` 把「英文界面」切到已上线。**用户确认前不要上线。**
- 根布局按请求读 cookie，原来静态预渲染的登录、定价、后台等页面改为按请求渲染（其余页面本来就是动态的）。

## 代码位置

| 文件 | 作用 |
|------|------|
| `src/i18n/locales.ts` | 语言列表、cookie 名、深合并等纯函数 |
| `src/i18n/request.ts` | 每个请求的语言与文案（含权限兜底） |
| `src/i18n/messages/zh.json` | 中文文案，**键名的唯一来源** |
| `src/i18n/messages/en.json` | 英文文案，只能有 zh.json 里已有的键 |
| `src/i18n/next-intl.d.ts` | 按 zh.json 做键名类型检查 |
| `src/components/LanguageSwitcher.tsx` | 中文 / English 切换 |
| `src/lib/i18n/format.ts` | 按语言格式化数字（中文 万/亿，英文 K/M/B）与日期 |
| `src/i18n/messages.test.ts` | 键对齐检查 + 已翻译文件不得含硬编码中文 |

## 翻译一个文件的步骤

1. 把界面文字移到 `zh.json`（按模块分命名空间，如 `nav`、`auth`、`pricing`），在 `en.json` 写对应英文。
2. 客户端组件用 `useTranslations("ns")`；服务端组件用 `getTranslations("ns")`（`next-intl/server`）。
3. 数字、日期用 `src/lib/i18n/format.ts`，不要手写「亿/万」。
4. 把该文件加进 `src/i18n/messages.test.ts` 的 `TRANSLATED_FILES`，防止以后又写回中文。
5. 电脑版和手机版都检查一遍（英文通常更长，注意换行和截断）。

不翻：数据管线（`src/lib/data/scheduler` 等）、后台 `/admin`、日志与错误上报里的内部文案。
