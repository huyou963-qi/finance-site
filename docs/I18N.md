# 界面多语言（中文 / English）

## 现状（阶段 0 已完成）

英文版面向**海外用户**，所以语言由**网址**决定，搜索引擎能分别收录中英文页面：

| 网址 | 语言 |
|------|------|
| `/macro`、`/`（不带前缀） | 中文（默认） |
| `/en/macro`、`/en` | English |

- 框架：`next-intl`（不分路由模式）。`src/middleware.ts` 把 `/en/...` 内部转到同一个页面，并通过请求头
  （`x-app-locale`、`x-app-pathname`）告诉服务端语言和去掉前缀的路径。**页面文件不用挪进 `[locale]` 目录。**
- 英文文案与中文深合并，**英文缺的键显示中文**，所以可以一页一页地翻，不会出现空白。
- 记住偏好：进入 `/en/...` 时写 cookie `NEXT_LOCALE=en`；之后打开不带前缀的页面会 307 到对应 `/en` 页面，
  所以还没改成本地化链接的跳转（`router.push("/x")`、`window.location` 等）也留在英文。切回中文走
  `/api/i18n/reset?to=...`，清 cookie 再跳中文页。
- 开关：功能目录里的 `site-language-en`（`kind: "setting"`，分组「站点」），默认 **开发中**。
  - 切换入口：电脑版顶栏右侧、手机版导航抽屉底部「Language/语言」，都经 `useVisibleFeatures().can("site-language-en")` 过滤。
  - 服务端兜底：没开放英文的身份打开 `/en/...`，根布局经 `/api/i18n/reset` 送回中文页（不会重定向循环）。
  - 上线：管理员在 `/admin/feature-access` 把「英文界面」切到已上线。**用户确认前不要上线。**
- SEO：英文**已上线后**，根布局才输出 `hreflang`（zh-CN / en / x-default）与 canonical；`robots.txt` 同时屏蔽
  `/admin` 与 `/en/admin` 等私有路径。
- 根布局按请求读请求头，原来静态预渲染的登录、定价、后台等页面改为按请求渲染（其余页面本来就是动态的）。

## 站内链接怎么写

- 用 `@/i18n/navigation` 的 `Link`（自动加当前语言前缀），不要直接用 `next/link`。
- 判断当前页面用 `useLocalePathname()`（中英文得到同一个路径），不要直接用 `usePathname()`。
- 其他拼地址的地方用 `localizeHref(href, locale)`。
- 页面自设 `alternates.canonical` 会覆盖根布局的 hreflang：翻译这类页面时要改成按语言输出
  （目前有 `/articles/[slug]`、`/equity/industries`、`/equity/sectors/*`、`/equity/stocks/[symbol]`）。

## 代码位置

| 文件 | 作用 |
|------|------|
| `src/i18n/locales.ts` | 语言列表、cookie 名、深合并等纯函数 |
| `src/middleware.ts` | `/en` 前缀转发、记住英文偏好 |
| `src/i18n/server.ts` | 服务端取本次请求语言（含权限兜底）、英文是否已公开 |
| `src/i18n/request.ts` | next-intl 每个请求的文案 |
| `src/i18n/navigation.tsx` | 本地化 `Link`、`useLocalePathname` |
| `src/app/api/i18n/reset/route.ts` | 清英文偏好并回中文页 |
| `src/i18n/messages/zh.json` | 中文文案，**键名的唯一来源** |
| `src/i18n/messages/en.json` | 英文文案，只能有 zh.json 里已有的键 |
| `src/i18n/next-intl.d.ts` | 按 zh.json 做键名类型检查 |
| `src/components/LanguageSwitcher.tsx` | 中文 / English 切换 |
| `src/lib/i18n/format.ts` | 按语言格式化数字（中文 万/亿，英文 K/M/B）与日期 |
| `src/i18n/messages.test.ts` | 键对齐检查 + 已翻译文件不得含硬编码中文 |

## 翻译一个文件的步骤

1. 把界面文字移到 `zh.json`（按模块分命名空间，如 `nav`、`auth`、`pricing`），在 `en.json` 写对应英文。
2. 客户端组件用 `useTranslations("ns")`；服务端组件用 `getTranslations("ns")`（`next-intl/server`）。
3. 数字、日期用 `src/lib/i18n/format.ts`，不要手写「亿/万」。
4. 把该文件加进 `src/i18n/messages.test.ts` 的 `TRANSLATED_FILES`，防止以后又写回中文。
5. 电脑版和手机版都检查一遍（英文通常更长，注意换行和截断）。

不翻：数据管线（`src/lib/data/scheduler` 等）、后台 `/admin`、日志与错误上报里的内部文案。

## 阶段 1 的取舍与遗留

- 定价页：套餐名、卖点、活动名由管理员用中文配置，英文界面按产品类型显示固定英文（`pricing.offers.*`），活动统一显示 "Promotion"。价格按 CNY 显示（英文为 `CN¥`），并提示目前只支持支付宝/微信。
- 首页公告：内容是管理员写的中文，英文界面照常弹出（只翻了按钮）。
- 注册手机号：见下文「海外用户只用邮箱注册」。
- 页面自设 `alternates.canonical` 的 5 个页面仍只指向中文版（见上文「站内链接怎么写」）。

## 服务端提示与邮件（已完成）

- 业务代码照旧抛中文 `Error`。auth 接口返回前用 `localizeServerMessage(message, requestLocale(req))` 换成英文：
  语言来自 `NEXT_LOCALE` cookie（浏览 `/en` 页面时由 middleware 写入），英文表在 `src/i18n/serverMessages.ts`，**键是完整中文原文**。
- **改了 auth 报错文字或新增报错，要同步改 `serverMessages.ts`**：`serverMessages.test.ts` 会扫描 `src/lib/auth.ts`、
  `loginThrottle.ts`、`sameOrigin.ts` 和 `src/app/api/auth/**` 里的中文字符串，漏登记即失败。
- 微信登录失败时错误放在回跳地址里，由登录页/个人账户页在浏览器端用同一张表翻译。
- 注册验证、找回用户名、重置密码三类邮件有英文版；英文用户收到的链接指向 `/en/...` 页面。管理员后台触发的重置邮件仍为中文（不知道用户语言）。

## 海外用户只用邮箱注册（2026-11 产品决定）

- **英文站注册可不填手机号**（只需用户名、邮箱、密码，邮箱验证照旧）；**中文站仍必须填写中国大陆手机号**。
- 「海外」= 请求来自英文站（`NEXT_LOCALE=en`）**且**英文界面对该访问者开放（`site-language-en` 权限）。只看 cookie 会被手动设置绕过，
  所以注册和改资料接口都经 `requestSignupChannel(req)`（`src/i18n/requestChannel.ts`）再判定；规则本身是纯函数
  `src/lib/auth/phonePolicy.ts`（有单测）。
- 英文站填了手机号仍按中国大陆号码校验（目前不接受海外号码）。
- 没有手机号的账号在英文站改资料时可保持为空；**已有手机号的账号不能在英文站清空**，避免中文账号借英文站去掉实名信息。
- 未改表结构：待验证注册表 `PendingRegistration.phone` 不可为空，不填手机号时存空串，激活时写成 `User.phone = null`。
- 已知限制：解绑微信仍要求账号有手机号（海外用户一般不用微信登录）。

## 翻译方式

**AI 初译 + 人工抽查**（2026-11 确定）。新增文案时由 AI 直接写 `en.json` / `serverMessages.ts` 的英文，上线前抽查关键页面
（注册、定价、付款）。术语保持一致：Nowcast（指标预测）、Insiders（持股监控）、Pro、credits（回测积分）。

## 功能页文案（阶段 2）

功能页文案量大、很多写在配置对象里，不用 next-intl 键名，改用**中文原文即键**：

- 代码写 `tr("宏观数据")`、`tr("共 {count} 条", { count })`。中文站 `tr` 原样返回（行为与改造前完全一致），
  英文站查 `src/i18n/text/en/*.json`（中文 → 英文，AI 初译 + 人工抽查），查不到显示中文。
- 客户端组件 `const tr = useTr()`（`@/i18n/TextProvider`）；服务端组件/`generateMetadata` 用 `await getServerTr()`。
  英文字典只在 `/en` 页面由根布局传给浏览器。
- 组件外的辅助函数带参数 `tr: Tr = identityTr`（不传就是中文），由组件把 `tr` 传进去；
  常量表（如 `REGIME_LABEL`）保留中文，在显示处 `tr(REGIME_LABEL[x])`。
- 改中文文案 = 改了键：同时改英文字典，否则英文站会显示中文（`textCoverage.test.ts` 会报缺失）。
- 不翻：数据位置的中文（`===` 比较、`case`、对象键、`includes` 等匹配、事件正文里的固定小节名），
  以及只给管理员看的 `*ModelDetails` 面板、`/admin`。

### 工具

| 命令 | 作用 |
|------|------|
| `npx tsx scripts/i18n/wrap-cjk.ts <路径…>` | 报告组件里未包裹的中文、需人工处理的中文 |
| `… --write` | 自动包裹并插入 `useTr`/`getServerTr` 与 import |
| `… --thread-helpers` | 组件外小写辅助函数加 `tr` 参数并在同文件调用处传入；字符串表读取处加 `tr` |
| `… --wrap-labels` | JSX 里显示 `{x.label}` / `{x.title}` / `{x.nameZh}` 等的地方加 `tr`（中文站不变） |
| `… --dict=a.json --sources=out.json` | 导出尚无英文的原文，交给翻译 |
| `node scripts/i18n/fix-tr-deps.mjs <路径…>` | 把 `tr` 追加进 useEffect/useMemo/useCallback 依赖数组（不改其他依赖） |

同一行写 `i18n-ignore` 注释的中文不处理（例如交给子组件自己翻译的原文）。
`src/i18n/textCoverage.test.ts` 的 `TRANSLATED_FEATURE_PATHS` 登记已翻译模块。
