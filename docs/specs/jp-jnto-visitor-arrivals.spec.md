# 日本 JNTO 访日外客人数接入 Spec

## 1. 目标与范围

接入日本政府观光局（JNTO）按月发布的访日外客人数长期时序，作为日本外需、服务出口和线下消费的高频补充。首批保存总数及韩国、中国、台湾、香港、美国五个核心来源市场，共 6 条原始人数序列；分市场按**国籍**统计，不代表出发地。

只保存 JNTO 表中月度人数水平。表内同比、累计值可以由基础月度人数计算，本批不重复入库。其余国籍、地区合计、目的别、访日消费和住宿分项留待后续专题批次。

## 2. 复用与口径检查

- 全局搜索 `jnto`、`访日`、`游客`、`visitor`、Japan overview 与 scheduler catalog；本地数据库同义词查询为 0 条，没有可复用的 Instrument、订阅或 provider。
- JNTO 的访日外客人数由法务省出入国管理统计推算，与“外国人正入国者数”、住宿旅行统计的外国人延べ宿泊者数、观光厅访日消费调查样本均不是同一事实，不拼接。
- FRED/现有 jpov 没有这组六条 JNTO 官方国籍月度人数。本批新建独立 provider，避免用二手商业镜像。

## 5. 定义、修订与断点

JNTO 根据法务省的外国人入境数据计算访日外客人数：排除以日本为主要居住国的永住者等，加入过境、寄港地上陆和船舶观光上陆等；驻在人员及家属、留学生也包括在内，乘员不包括。每次入境计一次，因此该指标是人次而不是去重人数。

修订生命周期必须保留：观测次月先给“推计值”，取整到百人；推计值发布两个月后更新为接近最终值的“暫定值”，精确到个位；次年 7 月法务省年计确定后，JNTO 再更新为“确报”。当前滚动表通常有最近两个月的推计值。订阅 `revisionLookback=24`，适配器每次解析完整文件、向 worker 返回回看窗口；现有不可覆盖版本账本记录新增及值变化。它证明抓取时点可见值，并不重建接入日前每个月的首发 PIT。

2020-2022 年因疫情和边境管制出现接近零的真实观测。这是经济事件造成的水平断崖，不是缺失值、统计定义切换或可删除异常值；解析器保留官方零值且要求月份连续。

## 6. 文件结构与失败保护

- Workbook 每年一张 sheet，自 2003 年连续到当年；标题必须含“YYYY年 訪日外客数（総数）”。
- 月份列由 `1月` 到 `12月` 的表头定位。2010 年后表中多出空白间隔列，禁止用固定列号。
- 每个月份水平列旁边的 `伸率` 是同比公式，明确忽略；年累计也不读。
- 目标源行必须各出现一次；历史完整年必须有 12 个月；当年只允许尾部空白；所有系列覆盖必须一致。
- 值必须是 0 到 20,000,000 的安全整数；文件头必须是 XLSX ZIP，线上文件限制 300KB 到 10MB。任何 schema、锚点、sheet、行或连续性变化均抛错，让 fetch_run 进入 FAILED，禁止静默写入。

## 7. 订阅与更新机制

- DataSource：`jp-jnto-visitor-arrivals`，`BULK_FILE`；provider：`jp_jnto_visitor_arrivals`。
- 发布包建议：`jp.jnto.visitor_arrivals`，6 条成员同包，平时 `probe_interval=24h`。当前已知下一发布时间应通过 seed/日历覆盖写成 2026-09-16 16:15 JST；9 月以后 JNTO 公布新一期 schedule PDF 后更新覆盖。
- 精确发布时刻后第一次拉取若文件尚未替换，日探测会继续检查；无新值时 worker 记 SKIPPED，不制造新观测。下载或解析失败走现有指数退避与滞后告警。
- 每次在线抓取保存哈希快照、URL、ETag、Last-Modified 和抓取时间。文件 URL 每期变化，因此 client 必须先从官方页发现链接。
