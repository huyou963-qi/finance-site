## 更新机制与边界

1. 工业、社零、GDP 仍走既有 adapter、官方代理、统一观测 writer；复用
   NBS 发布目录/附件 transport，不建立平行事实表或来源。首发只补较新期，
   API 相同期修订优先。源标题、列序、父级不符即报错；不以空值生成零。
   HTTP 超时且首发有明确该成员时允许使用首发；两路均不能给值仍失败。
2. 发布包规则和日历保持原有，fetch_run metadata 记录首发 URL 和是否补位。
   工业首发未列出的行业继续取其原始 UUID，不能借其他行业值。
3. 房地产办公/商业用房必须继承投资、施工、新开工、竣工、销售或库存父级及单位。
   旧模糊 ID 仅映射到明确的待售面积子项，其他父级使用不同 canonical ID。
   seed 修正名字、单位和 sourceSeriesKey；已有订阅 nextRunAt 不因重 seed 后移。
   目录拆为开发投资/施工交付/销售交易/待售库存/开发资金叶组。
   **历史口径仍须官方逐月回读核对，不声称本轮修好全部历史。**
4. 互联网行业 2025 年补充仅限年度、%、精确 cid/indicatorId 和已审核官方 URL；
   实际数值由源文本解析。不是信息服务业、服务业整体或月度累计同比的替代。
   未来年份继续依赖官方 UUID；若再次缺报需新官方证据，不假装此例外自动发现所有新年度公告。
