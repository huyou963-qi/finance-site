# SAFE 收付款父级定义修复（2026-10-29）

本轮 69 条差异均是银行代客涉外收付款分项名称缺少收入、支出或收支差额父级。官方金额和本库观测核对一致，不需要补值、推算或改调度频率。收入 21 条、支出 25 条、收支差额 23 条；范围以 `safeExternal/reviewedPayments.json` 的精确代码和订阅键为准。

证据：[SAFE 时间序列入口](https://www.safe.gov.cn/safe/2018/0419/8806.html)、[2026-10-20 原始工作簿](https://www.safe.gov.cn/safe/file/file/20261020/c8db913913c0403ab9df424464f672ac.xls)。四个工作表分别是人民币/美元计值、月度/年度。月度最新期为 2026-09，年度最新期为 2025。交易币种分项不改变工作表的计值单位；月表是当月流量，年表是全年流量，未季调，不是国际收支平衡表的权责发生制口径。

根因：原解析器用同名行的出现次数区分三种流向，生成稳定代码，但只给 BOP 子项拼接父级。修复为收付款子项也拼接原始区块名称，总项不重复拼接。代码、订阅键、数值、日期、单位和频率保持原样。69 条已审阅成员新增原表父级校验；未知或缺失父级、成员消失、行序导致语义改变时停止该域更新并报错，避免静默串项或被 seed 删除。

定义修复是离线、幂等、有界的：最多检查 69 条现存指标，一次 15 秒上限的 Serializable 事务，仅更新名称、简称、描述和 metadata，保留其他元数据。不下载历史、不删除或重建指标、不写 MacroObservation/版本账本、不改订阅或发布包 nextRunAt。校验 sourceId、精确 sourceSeriesKey 和原名称，遇到未经审阅的新定义则整批回滚；不存在的指标不恢复。

合并并部署后，在现有 worker/calendar 双锁保护下执行：

必须先切换到包含本次解析器的新版 worker release，再执行定义修复。旧解析器不产生收付款 sourceRowPath，提前写入新父级校验元数据会使旧版连接器拒绝更新。

```bash
npm run data:repair-safe-payments-definitions
```

也已纳入现有 `data:seed-audited-definitions`，防止后续部署遗失修复。修复后应核验 69 条完整名称和 sourceRowPath，并对照修复前的 instrument ID、观测数量/最新值、订阅规则及 nextRunAt。无需运行 SAFE 全域 seed、全历史回填或生产构建。香港资源预算为单连接、69 条小行更新、无新索引和常驻进程；失败时事务回滚，不盲目覆盖其他人工变更。

更新机制继续沿用 SAFE 官方滚动工作簿：月度发布包 24 小时探测及历史修订回读，年度成员低频探测；没有证据表明这 69 条存在调度滞后，名称问题不应触发整包重跑。
