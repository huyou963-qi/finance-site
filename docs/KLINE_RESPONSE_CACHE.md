# K线服务端共享缓存

`GET /api/data/klines` 在 Provider 外层使用香港网站既有 PostgreSQL 的 `mds.kline_response_cache`。所有用户、PM2进程共享，重启和部署不清空。覆盖 Yahoo 与东方财富；保留美股原始历史价格库、精确复权流程。这是可重建的响应缓存，不作为历史事实库。

## 缓存身份

SHA-256键：格式版本、实际Provider、规范化代码、周期、复权、limit、before、fromSec、toSec。SH600000/600000.SH别名共用，黄金复权归一为none；A/B/HK币种、现货XAUUSD与GC=F期货不混用。没有用户账号。同样查询参数的顺序不影响键。

最新请求不把当前秒数放进键，避免每秒变成冷缓存。显式范围保留精确Unix秒及Provider原有闭区间语义，before严格小于；半个区间、冲突参数和无效周期入缓存前拒绝。当前不同范围分别缓存，不强行复用重叠窗口，以免端点、复权或hasMoreOlder错误；不声称支持任意范围覆盖复用。

保存完整响应：OHLC、真实volume、精度、availableFrom、hasMoreOlder与来源说明。空历史页保存真实空值和分页终止，不把源站错误转换为空页。limit统一20–1000，单响应最大4MiB，超出要求缩小范围。

## 更新与超时

| 请求 | 新鲜期/重新检查间隔 | 硬过期，从成功检查开始 |
|---|---:|---:|
| 最新/近期15m、1h、4h | 60秒 | 15分钟 |
| 最新/近期1d、1w | 120秒 | 15分钟 |
| 已结束历史，前/后复权 | 1小时 | 24小时 |
| 已结束历史，不复权 | 6小时 | 24小时 |
| 成功空页 | 30秒 | 60秒 |

只有请求右端/before比“现在减一个完整周期再减48小时”更早，才采用历史策略。周线包含完整周边界，日线日期不等同已收盘；最新请求始终采用短周期，不猜测节假日。时间使用绝对Unix/UTC，服务器本地时区不改变键或过期；多个主机应保持时钟同步。

形成中的4h桶每60秒可重查小时数据，不等4小时；日/周线同理。历史复权可能因分红、拆股变化，每小时重查；不复权也可能被源方修订，不永久保存。成功新响应完整替换该范围，不能将新复权尾部拼接旧复权历史。

刷新发现重叠已结束K线的OHLC改变时，原子失效同数据源/代码/周期/复权下的其他范围，并撤销其旧刷新租约。形成中或刚结束48小时内的正常价格变化不触发整组失效。没有比较基线的最新窗口冷启动也失效同组旧范围，防止隔夜新口径与旧历史缓存复用。不同周期/复权不互相淘汰。重叠比较不能发现响应窗口之外的修订，也不构成完整公司行动版本账本；未检测修订仍由历史TTL限界。客户端已加载的历史不会由服务端缓存自动推送重算。

按需刷新：新鲜期内直接返回，过新鲜期后首个访问请求等待刷新。同进程同键Promise合并、一起等待；其他进程发现正在刷新且旧值尚未硬过期时，可立即返回注明“更新中”的旧值；冷请求等待胜出者。空闲股票没有不断抓源站的后台循环，后续访问才重查。

刷新失败按30/60/120/240/300秒退避并落库，跨用户/进程有效。失败不推进旧数据检查时间或硬过期；有效旧值返回“刷新失败”和检查时间，硬过期后只返回错误。空页短暂保留，避免历史窗口滚动后长期误判边界。

`payload.cache`、`X-Kline-Cache`区分hit/refreshed/stale，并提供checkedAt/freshUntil/expiresAt。checkedAt是Provider成功检查时间，不是源站成交或交易所发布时间。`Cache-Control: no-store`避免浏览器/CDN另行缓存掩盖过期。已有桌面和手机版来源说明显示降级文字。

**美股日/周线限制**：底层仍读取历史价格库，沿用完成交易日及30分钟冷却更新，不提供盘中实时日K。响应缓存重查不能让底层数据凭空实时，也不能消除源站报价延迟；盘中可查看15m/1h/4h。本功能不改变历史价格入库策略。

## 并发与故障

- 原子INSERT/ON CONFLICT领取90秒刷新租约，数据库事务/连接不跨HTTP取数等待。总刷新等待60秒，失败释放自己的锁；进程退出后租约到期恢复。
- publish/fail必须匹配当前所有者、租约仍有效。过期慢请求不能覆盖新结果、清除新锁。源站超时的晚返回也不能重新发布。
- 每进程最多8个不同冷键Provider调用、128个排队任务。排队10秒取消，取消任务不会晚启动。每缓存实例最多256个待处理键。PM2多个进程的总并发按进程数增长，不是全集群统一8。
- DB不可用时30秒熔断到临时进程缓存（最多100条/16MiB），相同请求仍合并并标注降级。恢复后重用共享缓存；降级时无法跨进程共享。数据库诊断不暴露给客户端。
- 热键访问时间写入每分钟限频，不记录逐用户访问，没有公开清缓存接口。算法改变时递增KLINE_CACHE_VERSION，旧格式等待清理。

## 容量与清理

每进程至多每分钟尝试一次数据库清理；跨进程用非阻塞事务级advisory lock协调。删除硬过期且无活动租约的缓存，按最近访问淘汰至10000条/256MiB序列化payload目标。60秒内突发与活动租约可暂时超限，JSONB和索引还有额外空间开销；DELETE释放行供复用，不代表物理文件立即缩小。

正常访问自动触发清理。低流量/夜间需要及时清理时，可将下面命令并入既有cron（只清理、不取行情）：

```cron
*/5 * * * * cd /opt/finance-site && npm run markets:cache-prune >> logs/kline-cache-prune.log 2>&1
```

无访问时未删旧行也不能通过读路径绕过硬过期。维护只处理派生缓存，不删除equity_daily_bar。`markets:cache-prune`输出条数、payload_bytes、活动刷新数；排障结合响应缓存状态和服务端[kline-cache]日志。
