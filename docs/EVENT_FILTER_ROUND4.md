# 事件筛选第 4 轮：Skill 私有投递与账号同步

日期：2026-10-28。承接尚未发布的第 3 轮，本轮本地实现与验证，未提交、未部署。继续沿用左侧来源分页与默认 180px 筛选器。

## 问题、假设与改动

原有 Skill 只能生成文件，网页只有按账号分区的浏览器 localStorage，没有账号私有接收接口，也没有云端更新检测。因此“Skill 已生成”不能表示“已同步到网页”。

本轮把可验证的闭环缩为：用户生成单包凭证 → Skill 执行环境投递 → 账号私有存储 → 页面刷新 → 复用既有筛选与主图选取。持续采集任务由外部执行环境负责；本轮不创建采集调度器，不修改共享事件库或相关性规则。

## 接口与身份

- `GET /api/user/event-packs`：沿用网站 Session，只能读取当前有效账号的云端包、版本和凭证有效期，禁止缓存。Bearer 投递凭证不能读取此接口。
- `POST /api/user/event-packs`：只接受包专属 Bearer 凭证，账号由凭证确定，不接受 userId；即使已经登录，单独的 Session 也不能作为 Skill 投递权限。
- `POST /api/user/event-packs/credential`：同源 Session + 当前页面 userId 创建或替换一个指定包凭证，30 天有效，原始值仅创建时返回。只持久化 SHA-256。
- `DELETE /api/user/event-packs/credential`：同源 Session 撤销指定包的凭证；保留已保存事实。重新生成凭证立即替换旧值。账号停用时读写均失效。
- 私有包以 `(userId, packId)` 为数据库主键，不进入公开 MarketEvent 查询；本地包与云端同名包也使用不同展示 ID 和偏好，不能按相同 externalId 覆盖或误合并无关事实。

## 更新与失败规则

请求包含稳定 deliveryId、baseRevision 和原事件包 document。先复用事件解析器和导入规划器校验整个批次，再以 Serializable 事务执行版本检查和写入，不部分接收错误记录。同包按 externalId 更新、保留未提交记录；不同包和不同账号独立。

最后一次成功投递的相同请求返回原回执及 duplicate=true，不增加版本。相同 deliveryId 改内容、旧版本更新或竞争写入返回 409；不自动覆盖。幂等回执只保留最后一次成功提交，旧批次在后续更新后重放会因版本不符被拒绝，不能回滚事实。网络失败重试原请求；修改过的批次使用新 ID 和确认后的版本。

请求流限制 1 MB，每批 1–1000 条，累计单包 2000 条且不超过 2 MB，每账号 20 个包和 20 个凭证。来源链接协议限制 HTTP(S)，禁止内嵌账号密码和危险协议，不请求这些 URL；事实真实性仍由采集执行方负责，接口格式校验不构成事实核验。

## 网页交互

- 登录后首次加载、页面可见时每 30 秒、重新聚焦和手动刷新时读取云端包。首次账号查询失败不启用匿名写入，提供确认账号的重试入口；账号变化立即停止显示旧账号包；不把旧账号事实转入新账号分区。
- 同步失败保留当前已加载内容，显示失败与重试入口。初次同步未完成或失败时不能把空集合宣称为“没有事件”。
- 包管理弹窗区分本地/云端及云端版本，包含凭证创建、有效期、替换/撤销与协议入口。原始凭证仅存在当前组件内存，关闭弹窗或切换账号即清除，不写浏览器存储。
- 文件导入仍留在本机，不自动上传。云端事实可跨设备读取，包开关、配色、筛选仍是各浏览器偏好；云端更新不能重新启用本机已停用包。当前轮云端包提供停用、导出和撤销投递；未新增云端事实删除功能。
- “已同步 N 个云端包”只表示读取成功。是否匹配内容、位于当前区间或可上图仍由统一选取流程与结果说明解释。没有用额外固定状态栏侵占 K 线高度。

## 验证循环与结果

1. 新建隔离 PostgreSQL 16 数据库，实际执行新增 migration；调用真实 API Route Handler，验证 Session/Bearer 权限边界、双账号隔离、包绑定、重试、版本冲突、错误批次不部分写入、大小限制、同源保护以及凭证替换/撤销/过期、账号停用。
2. 数据库并发测试：相同请求并发后只有一个版本；不同内容竞争同一个 baseRevision 时一个成功、另一个 409，原事实不丢失。测试日志中的 Prisma 写冲突是预期触发并转为 409，不是未处理异常。
3. 完整链路：真实 HTTP Bearer 投递 → 隔离 PostgreSQL → 真实 Session GET → Chromium 中实际存储 hook → 实际图表选取函数。验证到达后可见、同名本地包不变、云端停用后修订到达仍保持停用。
4. 1280 / 390 / 320px：真实 UI 和 hook，云端到达、独立 ID、停用/配色保留、失败保留/重试、凭证不落 localStorage、撤销、切换账号/退出，以及空集合加载失败说明；默认面板 180px，无页面横向溢出。此专项的接口响应为固定夹具，和上一项真实数据库链路分别验证。
5. 回归第 1–3 轮筛选、导入结果、配额失败与重试、范围冻结、包隔离、系统加载失败及分页去重。

全量单元/架构测试 1277 项通过。schema、lint、最终版本生产构建及全部专项检查通过；轮询专项还验证了页面隐藏不请求、恢复可见后按定时器读取更新。结果见本地验证产物 `.data/verification/event-filter-round4/`；未在生产启用或使用真实用户凭证，不宣称生产已验证。
