# 个股公告与财报每日批量更新

## 数据底层与范围

复用 `secEdgar.ts` 的 SEC transport、`writeSecFilingIndex` 的公告唯一写入入口、
`SecFiling` 唯一公告表，以及既有季度 extractor / snapshot writer / vintage writer。
不新增同义公告表或财务表。新增 SecFiling 字段只表达日批处理状态、重试时间和
从该公告提取的业绩附件证据；可从 SEC 日索引、submissions 和原文重建。

首版覆盖 equity_security 已登记 CIK 的公司，公告类型为 8-K、10-Q、10-K 及修订版。
外国发行人的 6-K/20-F、公司 IR 先于 SEC 的新闻稿、市场预期和 AI 摘要暂不纳入。
新闻稿保留原文摘录与附件，基础中文摘要仅提取可核对的信息，不将不确定的非 GAAP 数字写入标准三表。
首版只提取 EX-99 的 HTML 附件；PDF 等其他格式仍可通过公告原文的附件清单访问。

## 运行与调度

`npm run equity:sync-daily-disclosures` 每日一次，默认截至上一美东自然日，回看 7 天。
先下载日索引，再仅查询出现目标公告的 CIK 的 submissions。按 accession 去重；
已完成公告不再下载。待补齐/失败任务不限于回看窗口，持久化后持续按日重试。
完整财务数据仅在包含对应 accession 且 extractor 能产生对应版本时写入完成状态。
普通 8-K 仅入索引，不下载正文；每次最多深度处理 300 份财报/业绩公告，
单并发、任务间默认间隔 1 秒；超出部分持久排队，保留待处理。

参数：`--through=YYYY-MM-DD`、`--days=7`（最多 31）、`--symbols=AAPL,MSFT`、
`--max-filings=300`、`--delay-ms=1000`、`--dry-run`（仅计划，不访问外部源、不写库）。
`--timing-limit=20` 控制回看窗口内历史已完成财报的 header 补齐上限（0 禁用）；
核验失败保留已入库财务结果，并间隔七天后再尝试时点补齐，不逐日反复请求失败文件。
已尝试但失败的时点任务保留重试资格，不因离开七天发现窗口而丢失。
失败和待补齐分别计数，失败以非零退出；日志记录缺失的日索引（节假日可能无文件），
后续回看会重试。停机超过窗口时，用 through/days 分段补跑，不将漏日视为完整覆盖。

cron 替换原周度任务，每日北京时间 19:15（美东 06:15/07:15）执行；沿用部署自动安装的 sector-history cron。
服务器 cron 必须支持 CRON_TZ；若不支持，按 docs/US_EQUITY_SECTOR_ANALYSIS.md 的
部署说明核对 cron 时区，改为服务器当地的固定时间（香港推荐每天 19:15，覆盖全年美东日终）。
数据库 advisory lock 防止手工和定时任务重叠；flock 防止同机 cron 重叠。
部署流程同样等待该 flock，避免日批运行中替换依赖；上线不在部署会话内发起外部抓取。

## 页面与验收

### 基础中文摘要与事件时点

用户选择无需 AI 费用的规则摘要。只读取既有附件和按 accession 保存的财务版本，
不调用模型、不新增摘要事实表；缺少可靠数据时显示未提取，附可展开的原文依据。
GAAP 与非 GAAP 分开，缺少发布前预期快照时不输出超预期判断。8-K 的财务数字若来自
后续定期报告，须标明后续报告来源和日期；不得把最新重述值伪装成新闻稿首发数字。

时点沿用 SEC adapter / writer：submissions 的原始 acceptanceDateTime 单独留作审计；
精确 SEC 接收时间只由 SEC SGML 头的 ACCEPTANCE-DATETIME（美东墙钟）核验。
公司发布时间只认附件中带明确时区的 datePublished；只有可核对发布日期时保留日期精度。
只有日期且无时区时保留公司原文日期，不声称已换算为美东日期，也不计算市场反应。
新增 SecFiling 的 accepted/published 字段是既有公告的时点投影，不新建平行公告来源。
新业绩稿解析复用同一次正文下载；定期报告仅多读一个小型 header 文件。
历史完成公告按每日限额补齐 header；不为此重新下载 companyfacts，且页面不发外部请求。

事件收益是「明确时点之后的首个完整交易日收盘收益」，不是因果归因：盘前用前交易日
收盘到当日收盘，盘后/休市用前一个收盘到下一交易日收盘；盘中无法用日线隔离，留空。
精确时刻、官方交易日历、相邻交易日价格或目标日收盘尚不齐全时均留空。
业绩稿缺少公司发布时刻时，不把 SEC 接收时刻冒充业绩发布时刻；普通定期报告可单独
标注以 SEC 接收时点计算的申报后收益。已核对 NYSE 2025–2027 日历及 2025-01-09 特别休市；
超出日历范围不猜测。来源：https://www.nyse.com/markets/hours-calendars 。

### 每日批次与关联展示

新增 `mds.equity_disclosure_batch` 仅记录调度执行事实（范围、起止时间、覆盖 CIK、
缺失索引、失败 CIK 和处理计数），不是第二份公告或财务表。公告、附件、季度数据仍由
现有 writer 写入原表。批次记录无法从当前公告反推，需在持有既有 advisory lock 时创建；
全局批次与指定 symbols 的手动批次分开判定，dry-run 不创建成功记录。
每批只在发现结束和任务结束等阶段写入统计，不增加外部请求或轮询。
中断批次保留 running 证据，页面超过两小时视为异常，下一批在取得同一锁后标记其失败。
缺失索引、部分失败和积压不能呈现为全量成功；只有确认本股在范围内且公告发现完整，
才允许提示某日没有公告。北京时间 19:15 日批留两小时宽限，超期提示更新滞后。

同次业绩仅按明确报告期关联；业绩稿可用明确的 quarter/year ended 日期，或将标题财季
与 SEC 定期报告的实际财季及期末日期唯一核对。不能唯一核对时不关联，不按发布日期接近硬配。
修订版保留独立文件、日期与原文；筛选后再组合，不显示被用户过滤的公告。
入库时间、财务处理状态收进「更新详情」，业绩附件仍在各自原文下展开。

公告统一显示在个股「事件与叙事」分页，桌面与手机均在对应事件下展示入库时间、
财务更新状态及可展开的业绩附件摘录，不再在页顶重复列出公告。
事件接口通过 `details=1` 按需返回这些信息，行情图标记不携带附件正文；不新增轮询或外部抓取。
财务数据到齐后，既有财务基本面 API 的季度、TTM、估值和行业聚合读取新快照。
新闻稿发布不等于完整三表已更新，HTTP 成功但无对应版本不能计为完成。

部署需要 `npm run db:migrate`。迁移新增公告处理字段、索引和每日批次账本，不重写历史财务。
首次上线回看窗口内已有公告同样纳入处理；历史公告无需全量重拉。
