# 个股公告与财报每日批量更新

## 数据底层与范围

复用 `secEdgar.ts` 的 SEC transport、`writeSecFilingIndex` 的公告唯一写入入口、
`SecFiling` 唯一公告表，以及既有季度 extractor / snapshot writer / vintage writer。
不新增同义公告表或财务表。新增 SecFiling 字段只表达日批处理状态、重试时间和
从该公告提取的业绩附件证据；可从 SEC 日索引、submissions 和原文重建。

覆盖基本面覆盖范围内已登记 CIK 的公司（见下文「范围」），公告类型为 8-K、10-Q、10-K 及修订版。
外国发行人的 6-K/20-F、公司 IR 先于 SEC 的新闻稿、市场预期和 AI 摘要暂不纳入。
新闻稿保留原文摘录与附件，基础中文摘要仅提取可核对的信息，不将不确定的非 GAAP 数字写入标准三表。
首版只提取 EX-99 的 HTML 附件；PDF 等其他格式仍可通过公告原文的附件清单访问。

## 运行与调度

`npm run equity:sync-daily-disclosures` 每日两次，默认截至上一美东自然日，回看 7 天。
先下载日索引，再对每份新公告读取它自己的 SGML 头（`-index-headers.html`，几 KB），
从中取表单、申报日、报告期、8-K 数字 item、主文档与 SEC 接收时刻，一次请求同时完成索引与时点核验。
头文件缺失、与日索引表单不一致或申报人不含该 CIK 时，才回退到该公司的 submissions（数 MB）。
按 accession 去重；已完成公告不再下载。

范围（2026-11）：公告索引、companyfacts 下载、季度快照与 vintage 统一只覆盖基本面覆盖范围
（`fundamentalsCoverage.ts`：已有季度快照 ∪ 带 GICS 的标普成分 ∪ `index_constituent` 各指数最新成分），
重点为标普 500 与罗素 2000；批次记录的 covered_ciks 即此范围。`equity_security` 中其余公司
（约四千家，无历史财务可展示）不再每日入索引：个股页在库内无公告时仍会懒回补一次，之后不自动刷新。
全收的硬件成本其实很低（每行约 0.8 KB、约 100 MB/年），收窄是为了让公告、财务与价格使用同一份公司名单。
接入罗素 2000 只需把成分写入 `index_constituent`。显式 `--symbols` 时按名单处理，不受覆盖范围限制。

实测依据（2026-11-02 至 11-06 财报周）：全宇宙 6,070 个 CIK 中 2,178 家在 5 个交易日内有申报，
高峰日 1,300 份；旧实现逐公司拉 submissions（压缩后约 0.5 MB、亚洲访问 3–5 秒）并固定间隔 1 秒，
仅发现阶段就超过 cron 的 90 分钟上限，批次被杀后停在 running。现改为每份公告几 KB 的头文件，
不再固定间隔（共享 SEC transport 已限速至每秒 4 次以内，低于 SEC 的 10 次），
并以 `--budget-minutes`（默认 75）在到点前停止领取新任务，批次记为 partial，未发现的 CIK 计入
failedCiks（页面不会据此宣称当日无公告），未处理的公告留在持久队列由下一轮继续。待补齐/失败任务不限于回看窗口，持久化后持续按日重试。
`equity:sync-sec` 等路径写入的公告会留下 `daily_status=null`；日批除窗口内新发现外，
还会把近 `--backlog-days`（默认 120）天内已带 `report_period_end` 的 10-Q/10-K，
以及含 Item 2.02 的 8-K，重新收入待处理队列，避免财报季漏解析。
完整财务数据仅在包含对应 accession 且 extractor 能产生对应版本时写入完成状态
（营收、EPS 或净利润任一非空即可）。companyfacts / 原文先按票面 CIK 取，若与
accession 前缀不同（优先股联合申报或代报主体）再回退到 accession CIK。
普通 8-K 仅入索引，不下载正文；每次最多深度处理 1,000 份财报/业绩公告（实测约每分钟 15 份，
财报季高峰日约 1,300 份由两轮当天消化；原上限 300 使财报季积压数周），
单并发、仅受共享 SEC transport 限速；超出部分持久排队，保留待处理。

参数：`--through=YYYY-MM-DD`、`--days=7`（最多 31）、`--symbols=AAPL,MSFT`、
`--max-filings=1000`（1–1000）、`--delay-ms=0`（任务间额外等待，默认不加）、`--budget-minutes=75`、
`--dry-run`（仅计划，不访问外部源、不写库）。
`--timing-limit=20` 控制回看窗口内历史已完成财报的 header 补齐上限（0 禁用）；
`--filing-fallback-limit=12`（0–20；生产 cron 用 20）控制 companyfacts 滞后时的原文 XBRL 回补名额；
`--backlog-days=120`（0–366）控制窗口外 null 财报重新入队的申报日回溯；
核验失败保留已入库财务结果，并间隔七天后再尝试时点补齐，不逐日反复请求失败文件。
已尝试但失败的时点任务保留重试资格，不因离开七天发现窗口而丢失。
失败和待补齐分别计数，失败以非零退出；日志记录缺失的日索引（节假日可能无文件），
后续回看会重试。停机超过窗口时，用 through/days 分段补跑，不将漏日视为完整覆盖。

cron 替换原周度任务，每日北京时间 19:15（美东 06:15/07:15）与 11:15 各执行一次；第二轮用于消化
首轮未处理完的高峰日余量和 companyfacts 滞后，时间与持股、量化月任务错开。沿用部署自动安装的 sector-history cron。
服务器 cron 必须支持 CRON_TZ；若不支持，按 docs/US_EQUITY_SECTOR_ANALYSIS.md 的
部署说明核对 cron 时区，改为服务器当地的固定时间（香港推荐每天 19:15，覆盖全年美东日终）。
数据库 advisory lock 防止手工和定时任务重叠；flock 防止同机 cron 重叠。
部署流程同样等待该 flock，避免日批运行中替换依赖；上线不在部署会话内发起外部抓取。

## 页面与验收

### 基础中文摘要与事件时点

用户选择无需 AI 费用的规则摘要。只读取既有附件和按 accession 保存的财务版本，
不调用模型、不新增摘要事实表；缺少可靠数据时显示未提取，附可展开的原文依据。
GAAP 与非 GAAP 分开，缺少发布前预期快照时不输出超预期判断。8-K 的财务数字若来自
后续定期报告，须标明后续报告来源和日期；不得把最新重述值伪装成新闻稿首发数字。

时点沿用 SEC adapter / writer：submissions 的原始 acceptanceDateTime 单独留作审计；
精确 SEC 接收时间只由 SEC SGML 头的 ACCEPTANCE-DATETIME（美东墙钟）核验。
公司发布时间只认附件中带明确时区的 datePublished；只有可核对发布日期时保留日期精度。
只有日期且无时区时保留公司原文日期，不声称已换算为美东日期，也不计算市场反应。
新增 SecFiling 的 accepted/published 字段是既有公告的时点投影，不新建平行公告来源。
新业绩稿解析复用同一次正文下载；定期报告仅多读一个小型 header 文件。
历史完成公告按每日限额补齐 header；不为此重新下载 companyfacts，且页面不发外部请求。

事件收益是「明确时点之后的首个完整交易日收盘收益」，不是因果归因：盘前用前交易日
收盘到当日收盘，盘后/休市用前一个收盘到下一交易日收盘；盘中无法用日线隔离，留空。
精确时刻、官方交易日历、相邻交易日价格或目标日收盘尚不齐全时均留空。
业绩稿缺少公司发布时刻时，不把 SEC 接收时刻冒充业绩发布时刻；普通定期报告可单独
标注以 SEC 接收时点计算的申报后收益。已核对 NYSE 2025–2027 日历及 2025-01-09 特别休市；
超出日历范围不猜测。来源：https://www.nyse.com/markets/hours-calendars 。

### 每日批次与关联展示

新增 `mds.equity_disclosure_batch` 仅记录调度执行事实（范围、起止时间、覆盖 CIK、
缺失索引、失败 CIK 和处理计数），不是第二份公告或财务表。公告、附件、季度数据仍由
现有 writer 写入原表。批次记录无法从当前公告反推，需在持有既有 advisory lock 时创建；
全局批次与指定 symbols 的手动批次分开判定，dry-run 不创建成功记录。
每批只在发现结束和任务结束等阶段写入统计，不增加外部请求或轮询。
中断批次保留 running 证据，页面超过两小时视为异常，下一批在取得同一锁后标记其失败。
缺失索引、部分失败和积压不能呈现为全量成功；只有确认本股在范围内且公告发现完整，
才允许提示某日没有公告。北京时间 19:15 日批留两小时宽限，超期提示更新滞后。

同次业绩仅按明确报告期关联；业绩稿可用明确的 quarter/year ended 日期，或将标题财季
与 SEC 定期报告的实际财季及期末日期唯一核对。不能唯一核对时不关联，不按发布日期接近硬配。
修订版保留独立文件、日期与原文；筛选后再组合，不显示被用户过滤的公告。
入库时间、财务处理状态收进「更新详情」，业绩附件仍在各自原文下展开。

公告统一显示在个股「事件与叙事」分页，桌面与手机均在对应事件下展示入库时间、
财务更新状态及可展开的业绩附件摘录，不再在页顶重复列出公告。
事件接口通过 `details=1` 按需返回这些信息，行情图标记不携带附件正文；不新增轮询或外部抓取。
财务数据到齐后，既有财务基本面 API 的季度、TTM、估值和行业聚合读取新快照。
新闻稿发布不等于完整三表已更新，HTTP 成功但无对应版本不能计为完成。

### SEC 汇总接口滞后时的原始申报回退（2026-11）

已发布 10-Q/10-K 可能暂未出现在 companyfacts；日批不再只等待汇总接口。
缺少对应 accession、实际报告期或营收/净利润/经营现金流/资本开支时，读取该 accession
目录中唯一的 XBRL instance。仅接纳本 CIK、无维度、美元事实；累计数仍按真实起止日期
推导单季，必要时读取紧邻上一季度的申报，不把半年或九个月累计值当作单季。

现金资本开支扩展沿用逐公司已核实的标签白名单；需要合成时，必须核对唯一的合并现金流
主表、原始展示网络与英文行标题。CPT/KIM 的合并资本支出行，仅在完整主表确认旧单独
分项不再出现时接受，不能由“缺数字”推断分项为零。EQIX 接纳已核实的 Other PPE 购置行。
金额保留源精度；同一事实按不同显示精度重复时，只接受声明 decimals 可解释的舍入差异，
保留更精确金额，真实冲突继续失败。各原始文件 URL 与 UTF-8 文本 SHA-256 保留在补充输入。
联合申报列出多家公司现金流表时，仅允许用该 CIK、无维度 DEI 的注册全名与主表标题
后缀精确匹配（仅归一大小写、空白和 Co/Company 标准缩写），不能按出现顺序或公司名相似程度选择子公司的报表。
DTE 近年重新分列的 utility / non-utility 现金购置额，核对两条主表标题后同申报、同累计区间求和；
任何一项无数字均保留缺失，附注中的应付、未付资本开支不计入现金支出。
新版申报可能把 presentation/labels 内嵌在 XSD 中。仅读取 instance 明确引用的本申报
schema（最多 8 MiB），核对 targetNamespace；只解析 annotation/appinfo 下的 linkbase，
不递归下载 import/include。独立标签文件的命名也以该 schemaRef 为准，允许 instance 文件名
带 x10q 等后缀；内嵌模式的两份证明指向同一 schema 和同一哈希。每份文件预算仍不增加。
DLR 的 Improvements to investments in real estate 按现金流主表单列改善支出补取，
不把同表另列的业务/资产收购及合营投资计入资本开支。
PSA 2022 年仍使用维护及开发扩张两条现金支出主表行，仅在完整主表不列后来拆出的
property enhancements / energy efficiencies 时接纳两项合计；不把补充披露的应付/未付金额加入现金支出。
经营总收入与合同收入也需区分：AEP/CMS/CNP/D/ED/EVRG/NRG/PEG/PPL/VST 的合并利润表
总额使用 Revenues 或 RegulatedAndUnregulatedOperatingRevenue；合同收入另有衍生品等调整。
总额可能高于或低于合同收入，不能以“金额较大”或“末端更新”选择合同子项并回写历史。
上述发行人缺总额时保留缺失，原文回退继续补取实际总额；季度、年度与主表补充口径一致。

复用既有进程、锁、快照和重试状态，不新增常驻服务、表或索引。默认每轮最多读取 12 份
申报（`--filing-fallback-limit=0..20`），每公司最多本期及前期两份、串行处理；每份最多
目录、instance、presentation、labels、FilingSummary 五个文件，XML 上限分别为 32/8/8/2 MiB。
前期发现限制 220 天、最多两个历史索引文件。原文回补名额先给已经等待过的 10-Q/10-K，
再给修订版；没分到名额的申报保持待处理，不计入尝试次数，下一轮仍可立即重试。
连接中断会重试，读正文超时只再试一次；HTTP 404 不重试。真正的抓取失败和金额冲突
记失败并在 20 小时后重试，不会标为完整成功。页面和 API 仍只读数据库，不能在用户请求中触发批量原文回填。

部署需要 `npm run db:migrate`。迁移新增公告处理字段、索引和每日批次账本，不重写历史财务。
首次上线回看窗口内已有公告同样纳入处理；历史公告无需全量重拉。
