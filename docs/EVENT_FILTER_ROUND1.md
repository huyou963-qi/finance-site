# 事件筛选第 1 轮迭代记录

日期：2026-10-28。范围：筛选交互与响应式布局。本地实现，尚未部署。

用户反馈后已进一步压缩高度并恢复左侧来源分页，现行布局见 [紧凑版修订记录](EVENT_FILTER_COMPACT_REVISION.md)。下文保留第一版的迭代过程。

## 问题与改动

基线来自实现检查：常用筛选、来源与显示操作混在一排；高级条件折叠后缺少可移除摘要；最低重要度默认限制中等及以上，但未清楚展示为生效条件；手机使用即时生效的展开控件，缺少取消；原默认高度不足以容纳分层操作。

本轮假设：明确操作层级、减少默认展开的条件，并让条件可见、可撤销，可以减少误筛选。未采集真实用户任务耗时，不宣称成功率或速度提升。

已实现：

- 来源页签统一放在顶部。来源管理单独展开，系统来源开关和用户包管理保留；下载 Skill、导入范围和导入入口在手机与桌面均可操作。
- 内容区默认只展示搜索、类型摘要、重要度与更多筛选。类型与公司细类按需展开；支持全部类型与清空类型，清空后明确告知无结果。
- “仅宏观大预期差”归入宏观专属条件，说明会排除其他类型和缺证据的事件。已生效时即使类型变化，仍可从摘要移除该条件。
- 内容摘要显示搜索、类型、公司细类、重要度、宏观条件及各标签；每项可单独移除，折叠高级条件后仍能操作摘要。
- “清除内容条件”设置类型不限、重要度不限并清除搜索和标签；保留来源、包、关联范围、颜色、隐藏记录及上图设置。系统页另有“恢复资产默认”，只恢复内容与默认关联，不覆盖来源和展示设置；用户页无此按钮。
- 图表展示区与可滚动的内容区分开。本类上图、显示设置、列表布局单独管理。关闭上图后列表仍保留，显示明确提示。
- 手机筛选使用原生模态底部面板，编辑先暂存；应用才提交，取消或 Escape 丢弃；关闭后恢复入口焦点。
- 导入不再静默开启上图、清除大预期差或扩展类型；成功提示说明保留了原设置。完整“查看本次导入”与可见性诊断留待后续轮次。
- 桌面默认面板高度为 360px，手机最小 420px，桌面最小 300px，保留拖动调节；事件区域保留最小空间。手机搜索框独占一行以避免被挤压。

## 本轮内的验证与修正

1. 相关逻辑测试通过后运行浏览器交互检查。
2. 截图发现原高度挤压事件区，调整高度、滚动区域，并固定图表展示区的位置。
3. 320px 截图发现搜索框过窄，改为手机独占一行。
4. 增加焦点恢复断言后发现取消面板未恢复焦点，补充关闭清理逻辑，复测通过。
5. 构建发现公司细类数组类型过宽，增加受控类型过滤后重新构建。

保留本轮改动。当前依据是功能正确性、交互可达性和截图复核；是否改善真实使用效率，仍需在后续实际使用中观察。

- 本类上图关闭后事件卡片保留。

## 验证边界与下一轮

这是实际 UI 组件在固定夹具下的浏览器检查，未启动生产数据流，未验证真实账号、生产 API 或整页 K 线渲染。单元回归检查了标记开关和事件对齐，不能据此宣称已完成生产端到端验证。
