# 用户管理 P0–P2

管理员入口：`/admin/users`。列表由服务端按 25 条分页，支持用户名、邮箱、手机号和用户 ID 搜索，以及角色、账号状态、会员状态、注册日期筛选。列表遮盖邮箱和手机号；详情页才显示完整联系方式、会员/积分、最近订单、最近登录与管理操作审计。电脑端使用表格，手机端使用卡片。

## 上线顺序

1. 备份数据库，执行 `npm run db:migrate`。本次新增 `User` 账号状态、最近登录和管理员 TOTP 字段，以及 MFA 挑战、恢复码、登录尝试、账号事件、管理审计五张表。旧用户默认 `active`。
2. 在部署环境配置持久的 `ADMIN_MFA_ENCRYPTION_KEY`：32 字节随机值，编码为 64 位十六进制。可用 `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"` 生成。**不要更换或丢失此密钥**，否则已绑定的管理员验证器无法解密。
3. 首次启动前配置至少 12 位的 `ADMIN_PASSWORD`。新库不再使用默认管理员密码；已有库不会重置现有管理员密码。
   若旧管理员仍使用旧版示例中的默认密码，须在上线前通过旧版后台修改。
4. 部署后所有管理员须用密码重新登录，首次登录时绑定 TOTP 验证器并安全保存一次性恢复码。旧管理员会话在绑定完成前无法进入后台；管理员微信扫码不能绕过动态验证。
5. 验收：用测试账号检查搜索、筛选、分页、电脑/手机布局、停用后旧会话立即失效、恢复后可登录、角色变更后旧会话失效、审计记录、重置链接及管理员 MFA。

## 安全规则

- 管理员登录须密码加 TOTP；可用一枚尚未使用的恢复码替代 TOTP 登录。恢复码只在首次绑定时显示一次。
- 创建用户、修改资料或权益、停用/恢复账号、撤销会话、发送密码重置链接、重置另一位管理员的 MFA，都要输入操作原因、当前管理员密码和动态验证码。后台不再直接设置已有用户的新密码。
- 发送密码重置链接需要配置 SMTP；未配置时接口报错，不会向管理员显示“已发送”。
- 停用或关闭账号立即删除该用户所有会话；恢复停用账号不会自动恢复会话。关闭账号保留订单和审计记录，不能在后台直接恢复，也不等于隐私数据删除。角色或联系方式变更也会撤销目标用户会话。
- 不允许停用或撤销自己的管理员权限，也不允许停用或撤销最后一个有效管理员。重置管理员 MFA 只能由另一位管理员执行，被重置者下次登录须重新绑定。
- 管理操作审计保存操作者、目标、时间、原因及资料快照，不保存密码、TOTP 密钥或恢复码。
- 同一账号在 15 分钟内多次登录失败会临时限制尝试；邮件找回密码仍可使用。管理员应优先保护自己的密码和恢复码。

## 运维注意

现有仓库数据库 migration 必须按顺序部署。若本地数据库迁移历史与仓库不一致，先核对差异，不能跳过历史或直接强制应用。本次代码依赖新字段和表，**必须先迁移再启动新版本**。

单管理员丢失验证器且耗尽恢复码时，需由有数据库运维权限的人员按事故流程核验身份后处理；不要通过公开接口添加免验证登录捷径。建议至少配置两位管理员，并分别保管自己的恢复码。

## P1：会员、岗位与批量操作

- 最高管理员仍使用 `role=admin`。新增 `admin_support`（用户只读及统计）、`admin_membership`（用户只读、Pro 与积分、标签批量、导出及统计）、`admin_orders`（订单确认及用户只读）。所有后台岗位都必须使用密码和 TOTP 登录；普通功能页按普通用户权限判定，不能继承最高管理员的全站权限。只有最高管理员可以创建用户、修改资料和角色、停用/关闭账号、重置其他后台人员的 MFA。角色变更会撤销旧会话。
- `/admin/users/[id]` 提供明确的 Pro 到期日设置、延长 1–365 天、撤销以及积分增减（单次绝对值不超过 10000，余额不得为负）。手工操作须填写原因、当前后台人员密码与 TOTP，写管理审计；积分同时写 `credit_ledger_entry`。设置到期日按北京时间当日 23:59:59.999 生效。付费订单仍以独立订单及流水为准。
- 订单确认只允许最高管理员或订单处理岗位，须填写到账依据、密码和 TOTP。订单状态、用户权益/积分和审计在单个可串行化事务中提交，重复确认不会二次发放。
- 用户列表可按标签精确筛选；批量添加/移除标签先预览命中人数和最多 10 个用户名，再二次确认并重新校验结果。单次最多 500 位、预览 5 分钟失效。每位实际变更用户都有审计。CSV 导出也先预览人数、二次确认并重新校验筛选结果，最多 5000 位，含用户 ID、用户名、岗位、标签、状态、权益与日期，不含邮箱手机号；导出本身也留审计。只有最高管理员和会员运营岗位可批量与导出。
- 电脑端列表展示标签列，手机端卡片展示标签；详情中的会员表单、批量工具和导航入口在两端都可操作。只读岗位的详情联系方式遮盖，变更快照不返回。

## P2：生命周期统计与口径

入口 `/admin/users/analytics`，实时读取数据库，不保存个人级分析副本。所有总量排除已关闭账号和后台人员，统计时间在页面显示：

| 指标 | 口径 |
|---|---|
| 未关闭普通账户 | 当前未关闭且 `role=user`，包含已停用账户 |
| 邮箱已验证 | `emailVerifiedAt` 非空 |
| 近 30 天登录 | `lastLoginAt` 落在过去 30 天，不等于长期留存 |
| 试用中 / 试用已结束 | `trialEndsAt` 在当前时间之后 / 之前，且当前不享有有效 Pro |
| 当前 Pro | `plan=pro` 且到期日为空或未来；包含手工开通，故与“曾付费”不同 |
| 曾付费 | 至少一笔状态为 paid 的 Pro 订单，积分包不计入 |
| 14 天内到期 | 有明确 `planExpiresAt` 且在未来 14 天内；永久 Pro 不计入 |
| 曾付费但当前非 Pro | 曾有 Pro 付费订单且当前没有有效 Pro；这是权益流失口径，不等于主动退订 |
| 注册月 30 天付费转化 | 该月注册且目前未关闭的普通账户为分母；注册后 30 天内有 Pro 付费订单为分子。最近 30 天内的 cohort 尚未完整观察 |

标签分群展示每个标签当前命中人数，点击可跳到带标签筛选的用户列表。统计不推断试用历史：付费开通会清除当前 `trialEndsAt`，因此“试用已结束”不是历史全部试用人次。手工 Pro 也不计入付费转化或曾付费。

部署前先应用 `20261003090000_user_management_p1_p2` 迁移（添加用户标签及 GIN 索引），再启动新代码。上线后分别用四种后台岗位验证桌面与手机入口、只读限制、TOTP、会员操作、订单确认、批量预览和 CSV 导出。
