# 会员套餐与营销折扣

入口：账户菜单 → 会员与订单（/admin/orders）。最高管理员与会员运营可配置套餐活动；订单处理岗位只处理订单。桌面与手机均提供完整入口、表单、试算和发布操作。

## 发布操作

1. 在套餐设置中编辑月付、季付、年付的价格、展示状态与文案。默认月付39、年付421；季付109默认隐藏，须显式开启并发布。
2. 在营销折扣中设置活动名称、百分比减免（20表示八折）或固定直减、首次付费/续费/全部用户、适用套餐、北京时间开始和结束日期，勾选启用活动。
3. 填写变更原因、管理员密码和TOTP。保存草稿只写服务器草稿，不改变收费；发布上线将当前套餐及活动一起发布。
4. 日期范围内自动生效，结束日北京时间23:59:59后自动失效，不依赖定时任务；可随时停用线上活动。

发布采用配置版本校验，冲突时须重新载入。每次保存、发布和停用都记录操作者、原因与前后配置；后台列出最近10次操作，不存密码和TOTP。

## 成交规则

- 前台 /pricing 读取服务端的有效套餐和用户适用报价；未登录展示基础价。
- 新订单由服务端计算金额，客户端不能指定优惠或实付。已生成待支付订单继续付款时保持原成交价，不因活动到期、停用、套餐隐藏或改价而变化。
- 首次付费定义为没有历史会员收款记录（含需核对但已记录收款的订单），手工赠送权益和积分包不算付费会员。续费适用于有历史会员收款记录的用户，含已过期会员。
- 待支付且未过期的首购优惠订单占用首购资格；用串行化事务保护同一账户的并发下单。已过期订单可能仍由支付平台迟到确认，因此优惠资格以创建订单时锁定的快照为准，不追溯加价。
- 只应用一个活动，不叠加，积分包不参与。折扣按整数分四舍五入，最多抵扣至实付0.01元，不生成零元订单。
- 月付30天、季付90天、年付365天，一次性购买，不自动扣款。试用剩余天数和永久Pro保持既有规则。

## 唯一事实源与迁移

`public.billing_configuration` 单例是套餐及活动当前草稿/线上配置的唯一事实源；缺行时使用代码默认配置，保留旧价格且不启用活动。`billing_configuration_audit` 表达配置变更历史，与面向用户的权益调整审计分开。

`payment_order.pricing_snapshot` 保存报价版本、基础价、优惠、实付（均为整数分）、活动规则及权益周期。现有 `amount_cny` 为兼容支付及报表保留元金额，字段从整数升级为双精度以支持分；所有价格计算用整数分，发往支付平台以两位小数字符串表示，核验时转回整数分比较。不会重算历史订单。历史无快照订单按原有金额/周期处理。

复用现有 billing orders、zpayService、fulfillment、支付跟踪和审计权限；不创建第二套订单或支付发放服务。配置不能从浏览器草稿恢复；线上配置和审计须随数据库常规备份，代码默认值只用于尚未配置的系统。

上线前应用 `20261103120000_billing_campaigns`（`npm run db:migrate`），再启动新版本；自动部署已有迁移步骤。该迁移保留历史订单，新增配置及审计表、订单快照，并扩展金额精度，无删除数据操作。迁移前按常规备份数据库；金额字段类型变更会短暂持锁。
